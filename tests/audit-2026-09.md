# Test suite audit, September 2026

Scope: every test file in `tests/` (921 files), measured on Laravel 13.31, Psalm 6.18, PHP 8.5.
Question asked: which tests cost more than they prove, and where is the suite's runtime actually spent?

## Headline

The cost is not where file size suggests. The whole Type suite (767 `.phpt` files, 38 557 LoC) runs
in 31 seconds. The Unit suite (154 classes, 35 078 LoC, 1 909 cases) runs in 11 minutes 33 seconds,
and 692.6 of those 693 seconds belong to the 26 Unit classes that fork a real `vendor/bin/psalm`
subprocess. The other 128 Unit classes, including every file large enough to be flagged on LoC
(`ModelMetadataRegistryTest` at 1 992 lines, `ValidationRuleAnalyzerTest` at 1 205,
`SqlSchemaParserTest` at 1 021), cost under 2 seconds combined. LoC and wall-clock are effectively
uncorrelated here.

Three passes over all 921 files produced zero DELETE candidates. Every subprocess-fixture class
carries a docblock naming an issue number and stating why a `.phpt` cannot express the case. No
tautology (a test asserting the mock it just configured) was found. No test was found that would
still pass with its feature removed.

The defect is duplicated work, not duplicated tests. Of the 44 Psalm subprocesses
`BladeIssueRemapTest` spawned, 37 ran the byte-identical command in the byte-identical fixture
directory: one report recomputed 37 times and asserted 37 different ways. The fix already shipped in
this repo as a pattern, in `BladeTaintRemapTest`, which memoizes its report in a static and serves
six cases from one run.

## Classification

### Type suite: KEEP, with two moves

No DELETE. The checks that would find a vacuous `.phpt` all come back clean:

- Leading `%A` in `--EXPECTF--`: zero occurrences, and `bin/ci/phpt-leading-wildcard-allowlist.txt`
  is empty, which the convention script enforces.
- `@psalm-check-type-exact` stranded in a class or method docblock (silently dead, per
  `tests/Type/README.md`): zero confirmed. Three regex candidates were read and are correctly inline.
- Empty `--EXPECTF--` with no taint or opt-in `--ARGS--`: zero genuine cases. A naive grep returns
  232, but the default `tests/Type/psalm.xml` already runs at `errorLevel=1`, so a negative type
  assertion under plain defaults is legitimate.

MOVE (two misfiled files, both done in this change):

| From | To | Why |
|---|---|---|
| `TaintAnalysis/DispatchableEventsNamedArgumentL12.phpt` | `DispatchableEventsNamedArgumentL12Test.phpt` | Not a taint test. It asserts `InvalidNamedArgument` under plain defaults and was the only file in the directory without `--taint-analysis`. |
| `PromptInjection/TextResponseCollectionTypes.phpt` | `Collection/TextResponseCollectionTypesTest.phpt` | Asserts a generic-preservation fact under plain config, silently breaking that group's ARGS convention. |

Both bodies are byte-identical to the originals. Each picked up the `Test.phpt` suffix its
destination directory uses throughout.

MOVE (deferred): 77 root-level `.phpt` files belong in groups, and two new groups (`Console/` with 9
files, `Carbon/` with 4) are warranted on file count alone. Purely organisational, zero assertions
touched, but a large diff that deserves its own change. One naming clash has to be resolved first:
`Http/RequestTest.phpt` and `Request/RequestTest.phpt` already coexist.

MERGE (deferred, and only the safe half): roughly 20 taint files could fold into 5 where the
originals match distinct AST nodes or are pure negatives. The wall-clock payoff is zero (the whole
Type suite is 31 s), so the value is maintenance surface only, and that does not justify carrying
the batch-interference risk described under Traps. A second set, including the `TaintedSqlWhere`,
`TaintedSqlSchema`, `TaintedHtmlSessionStore` and `TaintedHtmlRequest` families, must not be merged
without an isolated re-run per original file.

Explicitly not duplicates, verified by reading bodies and expectations rather than names: the
`TaintedSqlWhere` family (35 files, one receiver-resolution branch each), `SafeInlineValidate` and
`SafeFormRequest` (about 72 files, one validation branch each, with every `*KnownLimitation.phpt`
pinning one documented soundness gap), `PromptGuard` (24 files, roughly half asserting escape and
half asserting survival), `TaintedNamedArgument` (9), and the version-gate pairs whose two halves
are complementary `skipFrom`/`skipBelow` sides of one assertion.

### Unit, Blade directory: KEEP all 44 classes

The directory holds 44 `*Test.php` files plus 5 shared helper classes. No DELETE. Every subprocess
class cites a specific issue and states why only a real run proves it. The two mock-only classes
(`BladeIssueRemapHandlerTest`, `ProjectFileInjectorTest`) pin the decline branches of a pipeline
whose accept path is covered end to end by `BladeIssueRemapTest`, so they are complementary rather
than tautological.

MERGE, in value order:

1. The 11 single-method `UnusedView*` sibling fixtures (613 LoC across 11 full Laravel app
   skeletons, about 56 fixture lines per assertion) into one shared root. Deferred: see Traps.
2. The five single-issue fixtures `EchoUnion`, `ErrorArgsOffset`, `ImplicitToString`, `ManagesLoops`
   and `NullableEcho`, whose `bootstrap/app.php`, `config/view.php` and `psalm.xml` are
   byte-identical (136 lines of pure copy out of 354). Deferred. `UndefinedThisProperty` must stay
   out: its `psalm.xml` adds `sealAllProperties="true"`, which would leak into the other four.
3. `TemplateContractTest` (36 lines, 2 methods on a 2-line accessor) into `ContractParserTest`.
   Deferred.

### Unit, everything else: KEEP all 110 classes

Zero DELETE, zero MOVE. Each file pins either internal logic, CLI behaviour or registry behaviour
(correctly Unit), or a whole-project regression that structurally cannot be a `.phpt`. The
subprocess classes state their own reasons, and they are not interchangeable with a type test:
`psalm-tester` always passes the snippet as an explicit file argument, so a bug that only manifests
under whole-program analysis over a config's `<projectFiles>` cannot be reproduced there;
phpt-declared classes are not Composer-autoloadable; the tester boots Testbench with no migrations,
so no model there ever has a populated schema.

One real correctness gap was found and is fixed in this change:
`ModelMetadataRegistryTest::relations_are_empty_without_a_populated_codebase` asserted only that
`relations()` was empty, never that the relations section was incomplete, so it could not
distinguish "codebase not populated, short-circuited" from "genuinely zero relations". That is
exactly the ambiguity its schema-section sibling was written to guard against. The fix is an added
assertion, not a deletion.

MERGE (mostly deferred): `EncrypterMethodResolutionTest` and `GuardMethodResolutionTest` share one
parametrised fixture runner in this change, which saves a Psalm run and about 80 lines of duplicated
harness. Still open: a `NestedStatementsTest` data-provider consolidation (judgment-heavy), several
small schema-directory merges (about 190 lines total), a shared trait for the reflection and
snapshot boilerplate duplicated across the three `ApplicationProvider*Test` files, and caching the
`foreign_id_for_pk_type` fixture that is currently re-parsed from disk once per method.

Two smaller flags, neither meeting a DELETE bar: `CommandDefinitionAnalyzerTest` admits in its own
docblock that 11 of its 12 cases exercise Laravel's console argument parser rather than the
analyzer, and `WarmUpFailureVisibilityTest` silently depends on another directory's fixture model
without stating the coupling.

### Application: KEEP

72 files and 3 102 LoC of app fixture, one driver script, one 24-line baseline that `-u`
regenerates. The README documents a deliberate single-domain design with each Laravel pattern
assigned to exactly one model, and no duplication was found. Note the cross-suite coupling below
before editing anything under `tests/Application/app/`.

## Traps

1. **Taint phpt batch interference is real here, not theoretical.** Co-analysing taint phpts in one
   ARGS group can silently drop cross-file findings. The repo carries the scars: 35 phpts run with
   `--threads=1` in their `--ARGS--` precisely because batching swallowed a finding. Any phpt merge
   must be verified by an isolated re-run per original file, never by a green suite, because a
   merged file that lost one of four findings still reports OK.

2. **Version-gated files look like duplicates and are not.** 98 phpts carry `--SKIPIF--`. Pairs such
   as `DateFacadeCreateL11` and `DateFacadeCreateL12` are complementary halves of a single
   assertion: on any one CI cell exactly one runs and the other skips, so "one of these always
   skips" is the gate working. Deleting either half silently drops coverage on half the matrix.

3. **Rector and php-cs-fixer skip globs assume a flat fixture shape.** `rector.php` skips
   `tests/Unit/Blade/Fixtures/*/bootstrap/cache/*` and `tests/Unit/Blade/Fixtures/*/resources/views/*`
   (the latter because Rector otherwise "fixes" the very defect a fixture exists to trigger), and
   `.php-cs-fixer.php` does the same for the cache directory. Both globs assume exactly one path
   segment between `Fixtures/` and `bootstrap` or `resources`. A fixture consolidation that nests one
   level deeper falls outside both excludes, and the style auto-fix workflow then commits the damage
   back to the branch. Keep fixtures flat, or update both globs in the same commit. This is why the
   `UnusedView` fixture consolidation is deferred rather than bundled here.

4. **`AnnotateEndToEndTest` mutates a tracked directory at runtime.** It writes `.blade.php` files
   into its fixture, lets the annotate pass rewrite them in place, then removes them. A `.gitignore`
   keeps `git status` clean, so a crash before cleanup leaves stray templates on disk that
   `git status` will not show, poisoning the next run. `BladeShadowPruneTest` shows the alternative:
   copy to a temp directory first.

5. **Shadow directories are shared between runs of one fixture.** Two configs analysed in the same
   fixture write to the same `.cache/blade-shadows`, and each run wipes it. Combined with
   `executionOrder="defects"` in `phpunit.xml.dist`, a case reading that directory live would assert
   against whichever run happened to go last. `AnalysesFixtureApp` snapshots the directory per run
   for this reason.

6. **Cross-suite fixture coupling.** The models under `tests/Application/app/` are simultaneously the
   Application suite's domain and the archetypes `.phpt` tests are required to reuse. An
   "Application-only" model edit changes the Type suite too.

## Result

Memoization keeps every assertion on its exact subject: the command and working directory are
byte-identical between the runs it collapses, so the JSON each case reads is byte-identical too.
Nothing was deleted, no assertion moved between cases, and no assertion was weakened.

| Metric | Before | After |
|---|---:|---:|
| Unit suite wall-clock | 693 s | 278 s |
| Psalm subprocesses in the Unit suite | 154 | 58 |
| Psalm subprocesses in the 13 memoized classes | 128 | 32 |
| Test classes | 154 | 153 |
| Cases | 1 909 | 1 909 |
| DELETE candidates found | 0 | 0 |

The Unit suite is paid once per CI matrix cell, so the 415 seconds come back on every cell.

Each ported class was checked for teeth rather than for greenness: a behaviour the class pins was
broken in `src/`, the set of failing methods was recorded before the port and again after, and the
two sets had to match exactly. A shorter failing list after a port would mean a case had started
reading a report a sibling case produced.
