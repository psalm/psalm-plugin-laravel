# Test suite audit, September 2026

Scope: every test bearing file under `tests/`. Measured on the `4.x` line (Psalm 7 beta, Laravel
13.31, PHP 8.5). Question asked: which tests cost more than they prove, and where is the suite's
runtime actually spent?

## Headline

The cost is not where file size suggests. The whole Type suite (758 `.phpt` files, 38 401 LoC) runs
in 27 seconds. The Unit suite (103 classes, 1 271 cases) runs in 55 seconds, and 54.2 of those 55
seconds belong to the 8 Unit classes that fork a real `vendor/bin/psalm` subprocess. The other 95
Unit classes, including every file large enough to be flagged on LoC (`ModelMetadataRegistryTest` at
1 972 lines, `ValidationRuleAnalyzerTest` at 1 203, `SqlSchemaParserTest` at 1 021), cost 0.62
seconds combined. LoC and wall clock are effectively uncorrelated here.

The passes over those files produced zero DELETE candidates. Every subprocess fixture class carries
a docblock naming an issue number and stating why a `.phpt` cannot express the case. No tautology (a
test asserting the mock it just configured) was found. No test was found that would still pass with
its feature removed.

## Inventory

| Suite | Files | LoC | Cases | Wall clock |
|---|---:|---:|---:|---:|
| Type (`.phpt`) | 758 | 38 401 | 758 (53 skipped) | 27.0 s |
| Unit | 103 classes | 22 080 | 1 271 (19 skipped) | 55.1 s |
| Application | 72 php files plus a driver | 3 102 | 1 Psalm run over a generated app | own CI job |

The Type suite batches its cases and runs them in parallel (95 s CPU at 456%). The Unit suite is
serial (50 s CPU at 98%). The Application suite is network bound (`composer create-project` into a
gitignored tree), runs as its own CI job, and is not part of `test:unit` or `test:type`.

### Where the Unit runtime goes

Eight classes fork Psalm. They are essentially 100% of the Unit runtime. One subprocess run costs
about 4 seconds and that figure is invariant to fixture size, so it is boot and scan cost, not
analysis.

|---|---:|---:|---:|---:|
| `Handlers/IndirectMethodReferencesTest` | 18.18 | 3 | 4 | 4 |
| `Handlers/ContainerNarrowedMethodResolutionTest` | 8.01 | 2 | 2 | 2 |
| `Handlers/UnknownModelAttributeEmissionTest` | 7.58 | 2 | 2 | 2 |
| `Handlers/UndefinedModelRelationDefaultsEmissionTest` | 4.22 | 1 | 1 | 1 |
| `Handlers/UndefinedRelationAutoloadCrashTest` | 4.17 | 1 | 1 | 1 |
| `Handlers/SuppressScopeUnusedCodeTest` | 4.12 | 1 | 1 | 1 |

**Memoizing a shared report does not apply on this line.** Every one of the 13 subprocess runs above
needs a command or a working directory no other run repeats, so there is no duplicated work to
collapse. `IndirectMethodReferencesTest` varies the config, the cache flags and the fixture on
purpose (Psalm's incremental cache is its subject). `UnknownModelAttributeEmissionTest` runs the
same fixture under `psalm.xml` and under `psalm-experimental.xml` to prove the severity promotion.
`ContainerNarrowedMethodResolutionTest` points at two separate fixture projects. The remaining five
are single run classes. A memo keyed on (command, working directory) would serve zero of the 13
runs from cache, so the pattern buys nothing here and is not worth the premise it deletes (see trap
4).

## Classification

### Type suite: KEEP, with two moves

No DELETE. The checks that would find a vacuous `.phpt` all come back clean:

- Leading `%A` in an `--EXPECTF--` issue line (it silently absorbs unasserted findings): zero
  occurrences, and `bin/ci/phpt-leading-wildcard-allowlist.txt` carries no entries, which
  `bin/ci/check-phpt-conventions.sh` enforces on every `test:type`.
- Empty `--EXPECTF--` with no taint or opt-in `--ARGS--` looks vacuous and is not. The default
  `tests/Type/psalm.xml` runs at `errorLevel="1"`, so a negative assertion under plain defaults
  asserts that Psalm found nothing at the strictest level, which is a real claim.

MOVE (two misfiled files, both done in this change):

| From | To | Why |
|---|---|---|
| `TaintAnalysis/DispatchableEventsNamedArgumentL12.phpt` | `DispatchableEventsNamedArgumentL12Test.phpt` | Not a taint test. It asserts `InvalidNamedArgument` under plain defaults and was the only file in the directory without `--taint-analysis`. |
| `PromptInjection/TextResponseCollectionTypes.phpt` | `Collection/TextResponseCollectionTypesTest.phpt` | Asserts a generic preservation fact under the default config, silently breaking that group's ARGS convention. |

Both bodies are byte identical to the originals. Each picked up the `Test.phpt` suffix its
destination directory uses throughout. Neither move changes co-analysis: the batcher keys its groups
on the normalised `--ARGS--` string, never on the directory, and both files kept their ARGS verbatim.

MOVE (deferred): the root of `tests/Type/tests` holds 77 files, several of which belong in existing
groups. Purely organisational, zero assertions touched, but a large diff that deserves its own
change. Naming clashes have to be resolved first: `Http/RequestTest.phpt` and
`Request/RequestTest.phpt` already coexist.

MERGE (deferred): some taint files could fold together where the originals match distinct AST nodes
or are pure negatives. The wall clock payoff is zero (the whole Type suite is 27 s), so the value is
maintenance surface only, and that does not justify carrying the batch interference risk described
under Traps. The `TaintedSqlWhere`, `SafeInlineValidate` and `SafeFormRequest` families must not be
merged without an isolated re-run per original file.

Explicitly not duplicates, verified by reading bodies and expectations rather than names: the
`TaintedSqlWhere` family (one receiver resolution branch each), `SafeInlineValidate` and
`SafeFormRequest` (one validation branch each, with every `*KnownLimitation.phpt` pinning one
documented soundness gap), `PromptGuard` (roughly half asserting escape and half asserting
survival), `TaintedNamedArgument`, and the version gate pairs whose two halves are complementary
`skipFrom` / `skipBelow` sides of one assertion.

### Unit: KEEP every class

Zero DELETE. Each file pins either internal logic, CLI behaviour or registry behaviour (correctly
Unit), or a whole project regression that structurally cannot be a `.phpt`. The subprocess classes
state their own reasons, and they are not interchangeable with a type test: `psalm-tester` always
passes the snippet as an explicit file argument, so a bug that only manifests under whole program
analysis over a config's `<projectFiles>` cannot be reproduced there; phpt declared classes are not
Composer autoloadable; the tester boots Testbench with no migrations, so no model there ever has a
populated schema.

One real correctness gap was found and is fixed in this change:
`ModelMetadataRegistryTest::relations_are_empty_without_a_populated_codebase` asserted only that
`relations()` was empty, never that the relations section was incomplete, so it could not
distinguish "codebase not populated, short-circuited" from "genuinely zero relations". That is
exactly the ambiguity its schema section sibling was written to guard against. The fix is an added
assertion, not a deletion.

MERGE (done): `EncrypterMethodResolutionTest` and `GuardMethodResolutionTest` pinned the same #1113
shape behind two copies of one subprocess harness and now share a parametrised runner in
`ContainerNarrowedMethodResolutionTest`. The two fixtures are separate projects, so each case keeps
its own Psalm run; only the harness is shared.

Two smaller flags, neither meeting a DELETE bar: `CommandDefinitionAnalyzerTest` admits in its own
docblock that most of its cases exercise Laravel's console argument parser rather than the analyzer,
and `WarmUpFailureVisibilityTest` silently depends on another directory's fixture model without
stating the coupling.

### Application: KEEP

72 files of app fixture, one driver script, one baseline that `-u` regenerates. The README documents
a deliberate single domain design with each Laravel pattern assigned to exactly one model, and no
duplication was found. Note the cross suite coupling below before editing anything under
`tests/Application/app/`.

## Traps

1. **Taint phpt batch interference is real here, not theoretical.** Co-analysing taint phpts in one
   ARGS group can silently drop cross file findings. The repo carries the scars: 42 phpts pin
   `--threads=1` in their `--ARGS--` precisely because batching swallowed a finding. Any phpt merge
   must be verified by an isolated re-run per original file, never by a green suite, because a
   merged file that lost one of four findings still reports OK. Moving a file between directories is
   safe on its own (grouping keys on ARGS), but changing its ARGS line moves it between groups.

2. **Version gated files look like duplicates and are not.** 73 phpts carry `--SKIPIF--`. Pairs
   whose names differ only by a Laravel major are complementary halves of a single assertion: on any
   one CI cell exactly one runs and the other skips, so "one of these always skips" is the gate
   working. Deleting either half silently drops coverage on half the matrix.

3. **Cross suite fixture coupling.** The models under `tests/Application/app/` are simultaneously
   the Application suite's domain and the archetypes `.phpt` tests are required to reuse. An
   "Application only" model edit changes the Type suite too.

4. **A case whose subject is cache or manifest state must never be served from a memo.**
   `IndirectMethodReferencesTest` runs Psalm repeatedly over one fixture and asserts on what a later
   run reads from an earlier run's cache. Collapsing those runs deletes the premise while leaving
   the assertion green, because the cold result happens to match. This is why the memoization
   pattern is recorded above as not applicable rather than as deferred.

5. **Rector and php-cs-fixer see the subprocess fixtures.** `rector.php` runs over all of `tests/`
   and excludes exactly two paths under it (a migrations directory and one macro fixture), plus
   three rules it turns off across `tests/*`. `.php-cs-fixer.php` excludes nothing. A fixture that
   exists to trigger a defect can therefore be "fixed" by the style auto-fix workflow, which commits
   the damage back to the branch. Add the fixture to both skip lists in the same commit that adds
   the fixture. `.phpt` files are outside both tools and stay byte identical.

## Result

Nothing was deleted, no assertion moved between cases, and no assertion was weakened.

| Metric | Before | After |
|---|---:|---:|
| Unit suite wall clock | 55.1 s | 55.1 s |
| Psalm subprocesses in the Unit suite | 13 | 13 |
| Unit classes forking Psalm | 9 | 8 |
| Test classes | 104 | 103 |
| Cases | 1 271 | 1 271 |
| Assertions | 3 430 | 3 432 |
| DELETE candidates found | 0 | 0 |

Runtime is unchanged by design. The subprocess count is a floor on this line, not an overhead: each
of the 13 runs is the only run of its command.

### How the change was checked

The merged class was checked for teeth rather than for greenness: a behaviour it pins was broken in
the plugin (the pre-#1113 full class shadow of `SessionGuard` was recreated as a stub), the set of
failing methods was recorded before the merge and again after, and the two sets matched exactly,
down to the same eight `UndefinedMethod` messages in the same order. The added registry assertion
was checked the same way, by forcing the relations section to be computed regardless of the
`codebaseMethodsInitialized()` guard: the pre-existing empty map assertion stays green and only the
new assertion fails.

The Type suite is verified by comparing its failing list against the same list on the base commit,
not by requiring a green run. A count alone cannot tell a fixed test apart from a newly broken one.
